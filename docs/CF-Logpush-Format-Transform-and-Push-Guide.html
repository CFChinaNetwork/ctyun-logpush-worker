Overview
🎯

Purpose

Transform Cloudflare edge access logs from the Logpush JSON format into the CDN partner 145-field format, and deliver them to the customer's log ingestion endpoint in near real time.

🏗️

Stack

100% Cloudflare-native: Logpush + R2 + Queues + Workers. No servers, no infrastructure to maintain, autoscaling by design.

📋

Log Format

145 fields, \u0001-delimited plaintext. Body gzip-compressed. Authentication via an MD5 URL signature.

⚡

Latency

Roughly 1–2 minutes end to end (dominated by the ~1-minute Logpush batch interval).

How It Works

Streaming, Bounded Parse

Raw files are read through DecompressionStream and transformed line by line; the Worker never buffers a whole file. Each batch (BATCH_SIZE = 2000 lines) is flushed to R2 and enqueued as it fills, so peak memory is bounded by the batch size, not the file size. Within one invocation a small pool (PARSE_PARALLELISM) parses up to that many files in parallel; max_batch_size must be ≥ that value.

Per-Read Idle Timeout

Each R2 read carries an idle timeout (PARSE_READ_IDLE_TIMEOUT_MS, default 45s). A read that stalls is aborted and only that one file is retried, so a single stuck object never blocks the queue. Because it is a per-read idle timeout (not a whole-file deadline), the same value is safe for any file size — a healthy large file emits chunks continuously and never trips it.

Idempotent Delivery (no receiver de-dup)

Queue delivery is at-least-once. The parser writes each batch under a deterministic key (processed/<safeKey>-<index>.txt); after a confirmed POST the Sender writes a .done marker. On any re-processing, batches that already have a .done marker are skipped, so a batch is never POSTed twice. A source-level .done additionally lets the parser skip a file it has already fully processed. The receiver needs no de-duplication of its own.

Self-Healing Dead Letters

Each main queue retries up to 5× and then dead-letters. The same Worker consumes parse-dlq / send-dlq and re-drives messages back to their source queue with exponential backoff + jitter. Transient failures recover automatically — no alerts, no manual draining. (Re-drive relies on the same deterministic key + .done markers, so it never causes a duplicate send.)

Streaming, Chunked Send

The Sender streams R2 object → gzip → fetch body, keeping memory per request small. The request uses HTTP/1.1 Transfer-Encoding: chunked (no Content-Length). The customer endpoint must accept chunked request bodies; HTTP 400 / 411 / 415 indicates it does not. Each POST is bounded by SEND_FETCH_TIMEOUT_MS (default 30s) so a stalled receiver is aborted and retried. Within one invocation a small pool (SEND_PARALLELISM) sends multiple batches in parallel; multiple invocations also run concurrently under the autoscaler.

CDN Node Country (Field #45)

The format requires the CDN node country (not the client country). EdgeColoCode (IATA airport code, e.g. NRT = Tokyo) is mapped to an ISO 3166-1 alpha-2 code via a built-in lookup table. If the code is empty or unmapped, the Worker falls back to SG.

MD5 Authentication

Workers' SubtleCrypto does not implement MD5, so a pure-JS RFC 1321 implementation is included. The URL signature is MD5({uri}-{ts}-{rand}-{privateKey}), sent as auth_key={ts}-{rand}-{md5}.

Timestamp & Content-Length

The parser auto-detects EdgeStartTimestamp in three formats (Unix seconds, Unix milliseconds, RFC 3339); configuring Logpush with timestamp_format = unix is recommended. Field #21 (sent_http_content_length) is populated from ResponseHeaders['content-length'] when Logpush Custom Fields are configured (optional — see Deployment); otherwise it returns -.

Deployment
Prerequisites: Node.js v18+ and Wrangler CLI locally; a Cloudflare API Token scoped to the target account with Workers Scripts:Edit, Workers R2 Storage:Edit, and Workers Queue:Edit. From your log partner, obtain the endpoint URL, the auth private key, and the target URI path.
This template is deployed once per domain. Replace the per-domain identifiers in wrangler.toml (marked 【按域名修改 / per-domain】 inline). See the Configuration checklist below.
1

Create the R2 Bucket

Dashboard → R2 Object Storage → Create bucket

  • Name: <domain>-com (must match bucket_name and [vars].R2_BUCKET_NAME)
  • Location: Automatic
2

Create the Queues

Dashboard → Workers & Pages → Queues → Create queue — create all four:

QueuePurpose
parse-queue-<domain>Triggers the Parser on each new R2 file
send-queue-<domain>Triggers the Sender on each processed batch
parse-dlq-<domain>Dead letters for parse — auto-consumed and re-driven back to parse-queue
send-dlq-<domain>Dead letters for send — auto-consumed and re-driven back to send-queue
3

Configure the R2 Event Notification

R2 → <domain>-com → Settings → Event Notifications → Add notification

  • Event type: object-create
  • Queue: parse-queue-<domain>
  • Prefix: logs/ (required — do not notify on the full bucket)
  • Suffix (optional): .gz
4

Set Worker Secrets

# Ingestion endpoint (base URL, no trailing slash)
wrangler secret put CTYUN_ENDPOINT

# Authentication private key
wrangler secret put CTYUN_PRIVATE_KEY

# Target URI path (e.g. /logpost/yourpath)
wrangler secret put CTYUN_URI_EDGE
Secrets are set once and persist in Cloudflare; they are not re-uploaded on each deploy.
5

Deploy

wrangler deploy        # or: push to main → GitHub Actions runs it
Expected output confirms producer + consumer bindings for parse-queue and send-queue, and a new Version ID.
6

Configure the Logpush Job

Dashboard → [Zone] → Analytics & Logs → Logpush → Create a Logpush job

  1. Destination: R2  ·  Bucket: <domain>-com  ·  Path prefix: logs/{DATE}/
  2. Dataset: HTTP requests
  3. Fields: Select all (the Worker handles missing fields gracefully)
  4. Timestamp format: Unix  ·  Sample rate: 1 (100%)
6b

Enable Content-Length Logging — Optional

To populate field #21 from the true Content-Length response header, configure Logpush Custom Fields via API (a one-time, zone-level setup; not available in the Dashboard UI). Add a http_log_custom_fields ruleset that captures content-length, then include ResponseHeaders in the Logpush job's field list. Without it, field #21 outputs -.

7

Verify End to End

Allow ~2 minutes, then check:

  1. R2: <domain>-com/logs/ contains .log.gz files
  2. Queues: parse-queue / send-queue "Messages Processed" is incrementing; DLQs near 0
  3. Worker logs: wrangler tail
# Expected (LOG_LEVEL=info)
[INFO] Parsing: logs/20260328/xxx.log.gz
[INFO] Done: logs/20260328/xxx.log.gz | lines=73 batches=1 errors=0 ...
[INFO] Sent 73 ... → HTTP 200 | processed/xxx.txt
HTTP 401/403 on send → check CTYUN_PRIVATE_KEY.   HTTP 404 → check CTYUN_URI_EDGE.
